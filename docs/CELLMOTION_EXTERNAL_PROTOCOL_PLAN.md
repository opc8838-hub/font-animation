# CellMotion 对外协议与现有动效标准化规划

更新时间：2026-09-07

## 结论

CellMotion 当前先暂停新增动效，优先逐个优化已有动效的编辑器、默认示例、尺寸适配、资源能力和真实导出。正式的对外协议不应现在一次性冻结；更合适的方式是保留统一方向，在文字、图标、媒体、粒子等代表性动效成熟后，从真实实现中提炼协议，再发布稳定的 `v1`。

现阶段要区分两件事：

- **内部功能基线**：我们开发每个动效时遵守的编辑器、资源、时间轴和导出要求，可以持续完善。
- **正式对外协议**：外部网站、开发者、AI 和 MCP 可以长期依赖的接口，一旦发布就需要兼容旧版本，因此应晚于功能探索。

背景视频就是不宜过早冻结协议的例子。如果先把背景定义成一个颜色值，后续加入视频，就会同时增加素材引用、裁切起止时间、循环、静音、解码、切换方式，以及预览与导出一致性等问题。当前应先把这些能力在代表性动效中做成熟，再决定公共结构。

## 什么是“对外协议”

对外协议可以理解为 CellMotion 提供给外部使用者的一套固定说明书和插座规格。它不规定动效内部必须使用 Canvas、SVG、DOM、粒子还是三维渲染，只规定外部如何识别、加载、控制和释放它。

例如，外部调用方式可以最终统一为：

```js
const motion = CellMotion.create({
  effect: "sprout-shift",
  target: "#hero",
  scheme
});

motion.play();
motion.pause();
motion.replay();
motion.seek(1.2);
motion.update(nextScheme);
motion.destroy();
```

字芽可以使用文字变形实现，点解可以使用像素处理，复杂动效也可以使用独立粒子系统。只要它们按能力声明提供可用的外部接口，就不需要拥有相同的内部结构。

## Prompt、JSON 和组件分别负责什么

| 形式 | 职责 |
| --- | --- |
| Prompt | 让用户用自然语言表达意图，例如“用字芽做一段 9:16 白底黑字的循环动效” |
| 方案 JSON | 精确保存文字、字体、图标、背景、尺寸、时间和动效专属参数 |
| 动效组件 | 真正加载方案并在网页中运行的代码 |
| MCP | 让 AI 查找动效、读取能力、修改方案、请求预览或导出 |

Prompt 不是稳定协议。AI 应把 Prompt 转换成经过校验的方案 JSON，再交给真实组件运行。否则每次都让 AI 重新编写动画，结果会漂移，也无法保证编辑器、网页预览和视频导出一致。

```text
用户语言 / Prompt
        ↓
     AI 或 MCP
        ↓
  CellMotion 方案 JSON
        ↓
  同一个确定性动效运行器
      ↙             ↘
   网页组件          视频导出
```

## 将来的协议应分成四部分

### 1. 动效清单与能力声明

每个动效公开身份、版本和经过验证的能力。没有验证的能力不能因为存在一个预览视频就被标记为可用。

```json
{
  "id": "sprout-shift",
  "name": "字芽",
  "version": "1.0.0",
  "capabilities": {
    "editableText": true,
    "inlineIcons": true,
    "videoBackground": true,
    "seek": true,
    "webComponent": false,
    "exports": ["png", "gif", "mp4"]
  }
}
```

能力必须来自实际验收。某个物理动效如果暂时不能精确跳帧，就声明 `seek: false`；某个编辑器没有完成 MP4 验证，就不能仅凭其他动效支持 MP4 而继承该标记。

### 2. 方案 JSON

方案保存用户作品。外层公共结构可以稳定，动效专属参数保留扩展空间。

```json
{
  "schema": "cellmotion/scheme-v1",
  "effect": "sprout-shift",
  "canvas": {
    "width": 1080,
    "height": 1920
  },
  "content": {
    "rows": [
      {
        "text": "让创意",
        "font": "Noto Sans SC",
        "color": "#111111",
        "icons": []
      }
    ]
  },
  "background": {
    "type": "video",
    "src": "background.mp4",
    "start": 1.5,
    "end": 6,
    "loop": true
  },
  "motion": {
    "speed": 1,
    "loop": true
  },
  "effectParams": {
    "characterDelay": 0.04,
    "scaleAmount": 0.8
  }
}
```

`canvas`、资源引用和生命周期属于候选公共结构；`effectParams` 由每个动效自己定义。路径、镜头、粒子、三维和多层动效可以拥有不同的专属结构，不应被强制改造成文字行模型。

### 3. 运行时接口

候选最小接口包括：

- `load()`：加载并校验方案。
- `play()`、`pause()`、`replay()`：控制播放。
- `seek(time)`：跳到确定性时间点；不支持的动效通过能力声明明确说明。
- `update(patch)`：修改文字、颜色或动效参数。
- `resize(size)`：重新适配画布。
- `destroy()`：释放事件、媒体和渲染资源。

网页导出和视频渲染不一定属于浏览器播放器本体，可以使用独立的渲染接口，但必须与预览共享时间轴和几何。

### 4. 状态事件

外部网站需要知道动效何时准备好、播放结束或失败：

```js
motion.on("ready", handler);
motion.on("play", handler);
motion.on("pause", handler);
motion.on("ended", handler);
motion.on("error", handler);
```

这样网页可以在一个动效结束时播放下一段，或者根据滚动、点击和业务状态控制组件。

## 如何兼容复杂动效

协议采用三层结构，而不是一张覆盖所有动效的巨大参数表：

1. **公共外壳**：身份、版本、画布、资源、加载和生命周期。
2. **专属参数**：下落速度、像素扫色、粒子密度、路径、镜头等由动效自己拥有。
3. **可选能力**：循环、精确跳帧、透明背景、网页交互、导出格式等逐项声明。

因此，统一的是连接方式和诚实的能力说明，不是把所有动画改成相同实现。

## 当前执行顺序

### 阶段 A：先优化已有动效

- 暂停新增动效。
- 按一个动效一个任务的方式迁移，禁止批量覆盖。
- 保留已批准的动效节奏、默认方案和卡片预览。
- 同步当前内部基线：尺寸适配、字体库、图标库、行级编辑、暂停修改、方案操作、时间轴和真实导出。
- 背景颜色、图片、GIF、视频、视频裁切和页面切换，只在该动效确实需要时接入，并完成预览与导出验证。
- 每个动效分别记录：视觉已确认、编辑器已完善、网页组件已适配、导出已验证。四种状态不能互相代替。

### 阶段 B：选择代表性样板

至少覆盖以下不同类型后，再收敛公共协议：

- 行或页面文字动效。
- 图标或资源编舞动效。
- 图片／GIF／视频背景动效。
- 粒子、物理、路径或三维中的一种复杂动效。

### 阶段 C：协议草案

- 从已经稳定的真实方案中提取公共字段。
- 定义方案校验、资源地址、生命周期和能力清单。
- 标记为 `draft`，允许调整，不向外承诺长期兼容。
- 用至少两个内部结构明显不同的动效验证。

### 阶段 D：冻结 v1 并交付

- 发布正式版本和兼容规则。
- 提供原生网页运行器；React、Vue 等只作为薄封装，不复制渲染逻辑。
- 组件页面提供在线编辑、方案 JSON、网页接入说明和明确的能力状态。
- MCP 读取同一份动效清单和方案结构，不建立第二套参数语义。
- 旧方案通过迁移函数加载，不能静默改变用户作品。

## 当前不做的事情

- 不因为网站组件库页面已经存在，就声称动效已经是可安装网页组件。
- 不一次批量重写全部编辑器。
- 不将预览 MP4 等同于网页组件。
- 不现在冻结一个覆盖全部复杂动效的正式 JSON Schema。
- 不把某个文字动效的行结构提升为粒子、路径或三维动效的通用模型。
- 不让 Prompt 直接绕过方案校验和真实渲染器。

## 何时适合正式制定协议

满足以下条件时，可以开始冻结 `v1`：

- 多种代表性动效已经采用稳定的编辑器和资源能力。
- 背景颜色、图片／GIF、视频及裁切模型已在真实预览和导出中验证。
- 旧方案迁移方式明确。
- 至少一个简单动效和一个复杂动效能够由统一外部接口控制。
- 能力标识可以通过自动检查或真实导出证明，而不是人工猜测。

在此之前，Skill 继续维护内部开发决策；正式对外协议保持为规划，不作为已经交付的产品承诺。
